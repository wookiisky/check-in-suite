# 小小成长岛：产品描述

> 版本：首版产品方案，2026-10-29 更新。正式开发已获批准，完成状态与实际证据见 [开发计划](../tasks.md)。用户确认保持 KISS：CLI 负责初始化和忘记密码恢复，网页保留姓名及两种密码修改；退出管理后再次进入必须重新输入管理密码；不开发备份，不进行真机验证。其余实施参数采用技术方案推荐值。

## 1. 产品目标与范围

小小成长岛是面向一个小朋友的日常任务打卡网站。小朋友完成任务，记录当天的照片、文字或声音，获得金币和钻石，再兑换称号、形象、饰品及家庭约定的奖励。家长使用同一个账户，通过管理密码调整任务、纠正记录和兑现奖励。

产品强调轻松、鼓励和清楚的反馈，不设置公开排行、惩罚机制、社交比较或复杂等级系统。

### 静态原型阶段交付（历史基线）

- `docs/product.md`：页面、业务规则、状态、交互边界和验收标准。
- `design/`：集中存放本地静态原型、素材、配置、测试与预览图，完整演示主要页面、弹窗与状态，适配桌面和手机。产品文档仍位于 `docs/product.md`。
- 示例数据只用于体验设计；原型中的登录与管理密码不构成真实权限保护。
- 拍照、录音、保存等媒体流程可用模拟状态表达，界面须明确标示演示性质，不将模拟数据宣称为真实录音或云端保存。
- 原型阶段不部署网站、不接后端；正式首版仍不提供账户注册、多人切换或跨设备同步。

### 静态原型实现与限制（历史基线）

- 默认直接进入示例营地，便于查看设计；从右上角退出后可体验登录流程。初始示例用户名为 `island`，登录密码为 `1234`，管理密码为 `8888`。这些只是演示数据，不可用于正式网站。
- 姓名可以修改并用于页面展示；登录用户名只读。密码表单演示旧密码、新密码及确认密码流程。
- 数据保存在当前浏览器的 `localStorage`，刷新后可以继续体验，并提供重置示例数据的入口。它不等于云端存储；更换浏览器、清理站点数据或重置会影响这些本地数据。
- 图片支持真实的本地选择和预览，原型单张图片限制为 2 MB，不上传至服务端。
- 录音仅演示计时、停止、重录和试听状态，不采集真实声音；试听播放示例短音。录音播放器的暂停能力属于正式产品要求，本次短音演示不代表真实录音播放器已完成。
- 背景音乐使用浏览器合成循环声音，默认关闭，由用户主动开启；它用于展示音乐开关体验，不代表最终音乐素材。
- 管理记录支持内容编辑；纠正日期或项目采用删除后补录。删除扣回原奖励，补录按当前项目配置重新计算奖励，操作前应明确这一影响。
- 原型阶段没有后端服务，无法证明真实登录安全、跨设备同步、多人并发、上传可靠性或长期数据保存能力。

### 已确认的边界

| 项目 | 决定 |
| --- | --- |
| 使用对象 | 单个账户、单个小朋友，不切换小朋友 |
| 身份关系 | 无管理员等角色，管理密码只用于解锁配置与奖励兑现 |
| 姓名 | 小朋友姓名或昵称单独配置，与登录用户名分开 |
| 记录编辑 | 普通界面只能修改、删除或重新打卡今天的记录；历史记录由管理界面处理 |
| 余额 | 允许负余额；删除记录时仍须回收原奖励 |
| 视觉 | 卡通冒险游戏风格，以森林成长营地为主场景 |
| 时间 | 站点固定采用 `Asia/Taipei`；周一为每周第一天 |

## 2. 页面结构

```text
登录
└─ 成长营地（主界面）
   ├─ 已完成记录：日视图位于左侧；周视图可跨页面宽度
   ├─ 今天的任务：日视图位于左侧；周视图位于记录区下方左侧
   ├─ 右侧：金币与钻石、角色形象、称号、商店入口、留言板
   ├─ 月历 → 日期详情 → 打卡记录详情
   ├─ 统计 → 时间范围 → 各项目累计次数
   ├─ 商店 → 商品 → 购买确认
   │        ├─ 我的装扮 → 装备 / 卸下
   │        └─ 我的奖励 → 待兑现 / 已兑现
   └─ 配置 → 管理密码验证 → 管理界面
            ├─ 账户与密码
            ├─ 类别与项目
            ├─ 打卡记录
            └─ 商店配置
```

桌面日视图采用左右两栏，左侧是记录与今日任务，右侧放角色与家庭留言。周视图的记录区允许跨页面宽度，给七天记录留出阅读空间；其下仍是今日任务在左、角色和留言在右。手机先展示记录和今日任务，再展示包含余额的角色区域与留言板，保留商店与配置入口，不通过缩小字体塞入桌面布局。

## 3. 账户、姓名与管理密码

登录使用用户名和密码，不增加角色选择。首版提供一个初始化账户，不开放注册。小朋友的姓名或昵称展示在主界面姓名入口、角色区域和统计页；改名后统一更新，不改动历史记录或积分。姓名不能为空，前后空格不作为姓名内容。

配置按钮位于主界面右下区域。点击后输入管理密码，验证成功进入管理界面。密码错误时就地提示并允许重试；退出管理界面或退出登录后恢复锁定。原型可以演示此流程，但正式开发必须在服务端验证管理权限。

“账户与密码”包含姓名设置、修改登录密码、修改管理密码。修改密码输入旧密码、新密码和确认密码；不一致或旧密码错误时保留表单并提示具体字段。姓名修改不要求重复输入管理密码，前提是已进入管理界面。

账户初始化和忘记密码恢复使用本机交互式 CLI；网页仍提供两种密码修改。两种密码均为 10–128 个 Unicode 码点，登录有效期七天，管理授权最长三十分钟；退出管理即撤销授权，再次进入必须重新输入管理密码。

## 4. 主界面与记录查看

### 日视图

默认显示今天，只展示所选单日的记录，不显示一整周的日期条。提供前一天、后一天和今天按钮。每条记录展示大图标、记录时的项目名称和打卡时间，不展示金币、钻石分值；有附件时显示照片、文字或录音标记。点击记录进入详情，详情同样不展示分值，重点呈现完成内容与附件。

没有记录时给出温和的空状态，引导查看今日任务，不显示失败或惩罚。

### 周视图

桌面按周一至周日排列七列，直接展示每一天的记录，而不是只显示日期或次数后再点击查看。每条记录包含大图标、名称和时间，不展示金币、钻石分值；没有记录的日期也保留完整分组并显示空状态。标记今天，支持前一周、后一周与本周。

手机将同一周的七天纵向排列，完整展示各日记录，不需要逐日点击，也不缩小文字。无论桌面还是手机，都可以点击具体记录打开详情。不能仅用颜色区分今天和空状态，应同时提供日期、文字或标记。

无论上方查看哪一天或哪一周，下方任务区始终是“今天的任务”。历史日期的只读提示须清晰，避免将今天的打卡误认为补卡。

### 今天的任务

按类别展示今天启用、适用于今天星期且仍有剩余打卡次数的项目。项目卡只展示大图标、名称、每次金币与钻石奖励，不放描述、次数小字或重复的操作说明。整张卡片都是打卡入口，键盘也能触发。

达到每日次数上限后，项目从今日可打卡区移除；完成记录继续保留在上方记录区，今天的记录仍可查看和修改。允许一天多次打卡的项目，在尚未达到上限时继续显示。删除记录释放今天的次数后，只要项目仍启用并适用于今天，就重新出现在可打卡区。

任务可按类别筛选。某类别没有可打卡项目时，不用空列表占据主要区域；今日任务全部完成时显示简短的完成状态。如果今天原本没有配置任务，则提示可在配置中添加任务，两种状态不能混淆。

## 5. 打卡、修改与删除

### 新增打卡

1. 点击项目，打开打卡弹窗，展示项目名称和本次奖励。
2. 可添加一张照片、一段文字、一段最多 60 秒的录音；三项均为选填，允许直接打卡。
3. 点击确认才创建记录、占用一次次数并发放奖励。取消、关闭或失败均不发放奖励。
4. 成功后关闭弹窗，更新记录、剩余次数与余额；达到上限的任务卡移除，未达到上限的保留。播放一次短促的成功动效；如果开启音效，可播放反馈音。

提交期间禁用重复确认。失败保留已填写内容，允许重试。正式实现应保证一次提交只产生一条记录，避免网络重试重复发奖。

### 照片与文字

照片支持拍照入口，并提供选择已有照片的替代方式；可以预览、替换、移除。文字在关闭未保存弹窗时提示是否放弃。具体文件体积、格式与文字长度在正式开发前确定，原型展示布局与错误状态。

### 录音

状态依次为“未录音 → 录音中 → 待试听 → 已选择”。开始录音后显示计时和停止按钮；到 60 秒自动停止并进入试听状态。试听支持播放、暂停，重新录音替换原录音，移除录音不影响文字与照片。

录音时暂停背景音乐，结束后按用户此前的声音设置恢复。离开弹窗时停止采集或模拟计时。麦克风不可用、未授权或录音失败时提示原因，允许使用其他方式完成打卡。

### 修改与重新打卡

普通界面仅允许编辑今天的记录。修改照片、文字、录音不新增次数、不重复发奖；“重新打卡”表示替换这条记录的内容，仍保留原日期、原奖励和记录身份。普通编辑弹窗不展示金币、钻石分值，日期、项目及奖励也不能在其中修改。

删除后重新新建是一条新的打卡，需要重新检查当天的项目安排和次数限制。

### 删除与负余额

删除前展示项目和将扣回的两种奖励。确认后记录不再参与列表、每日次数和统计，扣回该记录原先获得的金币、钻石，并释放一次当日次数。删除今天的记录后，符合今日安排且仍启用的项目重新进入可打卡区。

余额不足也允许删除，已购买的装扮和奖励保留。例如获得 10 金币后花掉 8 金币，删除原记录时余额从 2 变为 -8。界面同时展示负余额与“继续打卡可补足”的说明，不隐藏负数或自动改成零。

## 6. 月历与统计

### 月历

点击主界面“月历”按钮打开月视图。支持切换月份和回到本月，按周一至周日排列；桌面为七列，390 px 手机按周分组纵向展示日期，保持大字及 56 px 操作目标。每日显示日期、有效打卡次数及任务图标；图标过多时显示数量摘要，不将单元格无限撑高。

点击日期打开当日详情，展示记录的图标、名称、时间及附件，不展示金币、钻石分值；普通记录详情和编辑界面遵循同一展示规则。没有记录时展示空状态。今天可以进入普通编辑流程；过去日期只读；未来日期可查看为空，但不能创建打卡。

### 统计

点击主界面“统计”按钮打开统计页，姓名展示在页首。默认选择本月，提供本周、本月、近 7 天、近 30 天和自定义日期范围，范围两端均包含在内。本周、本月统计截至今天；近 7 天包括今天与此前 6 天。

核心指标是每个项目在范围内的累计有效打卡次数，以横向条形图和带数值的明细列表展示，默认次数从多到少排列。摘要展示总打卡次数和有打卡的天数，不用金币替代任务次数。

统计规则：

- 每条有效记录计一次，同一天同一项目多次打卡分别累计。
- 删除记录不计入；修改文字、照片或录音不增加次数。
- 补卡按记录所属日期统计，不按操作发生日期统计。
- 项目按稳定标识归组，改名不拆成两个项目；明细可使用项目当前名称，历史记录仍保留原名称。
- 停用或删除任务不抹去历史贡献，已有记录继续参与统计。
- 自定义开始日期不得晚于结束日期；结束日期不得晚于今天。非法范围直接在筛选区域提示，不展示误导的统计结果。
- 无数据时显示零和空状态，不伪造示例成绩。

## 7. 角色、商店与奖励

### 角色区

右侧上方展示可用金币、可用钻石，下面是角色形象、当前称号和已装备的饰品，最多同时展示 10 个饰品。余额是可以用于购买的当前数量，不能和累计获得数量混用。姓名展示在角色区域，商店按钮保持可见。

商城购买的装扮在装备后直接展示于主页形象区：形象替换角色外观，称号显示在角色旁，背景铺在画布最底部，透明饰品呈现在角色身上或周围，特效覆盖整个画布。桌面和手机使用同一套相对坐标，保持相同布局；素材不遮挡页面操作。

### 商品类型

| 类型 | 购买规则 | 使用方式 |
| --- | --- | --- |
| 称号 | 永久拥有，不重复购买 | 同时启用一个，可切换或卸下 |
| 形象 | 永久拥有，不重复购买 | 同时启用一个，默认形象始终可用 |
| 背景 | 永久拥有，不重复购买 | 同时启用一个，固定在最底层；卸下恢复默认背景 |
| 饰品 | 永久拥有，不重复购买 | 同时最多装备 10 个不同饰品，可移动、等比缩放及调整层级 |
| 特效 | 永久拥有，不重复购买 | 可以同时佩戴多个，固定覆盖画布，只能佩戴或移除 |
| 文本奖励 | 可以重复购买 | 每次购买生成独立待兑现记录 |

商品包含名称、类型、图标或展示素材、描述、金币价、钻石价和库存。两项价格都为零表示免费；两项都非零时需要同时支付两种货币。库存为非负整数或“不限量”，有限库存为零时显示售罄。

购买前展示商品、需扣的两种货币和购买后的余额；需要同时满足两种货币余额均不小于对应价格、库存可用且永久商品未拥有。负余额时即使某项价格为零，也不能绕过余额判断完成购买。确认成功后扣余额、扣库存、发放物品。库存、价格或余额变动导致购买失败时，不做部分扣款。

### 我的装扮

展示已拥有的称号、形象、背景、饰品和特效，并区分已装备与未装备状态。购买成功后进入“我的装扮”，不自动装备或替换当前装扮；装备操作不再次收费，成功后立即更新主页形象区。背景、形象和特效不占饰品的 10 件额度。素材仅从内置目录选择，不提供图片上传。

称号和形象分别同时启用一个，切换时替换对应展示；卸下称号后不再展示称号，恢复默认形象后展示内置角色。饰品可同时装备 0–10 个，新增一个饰品不替换其他已装备饰品，同一饰品不能重复装备。展示当前已装备数量与上限；达到 10 个后，继续装备其他饰品时提示先卸下一个，保留现有装备状态。该上限只限制同时装备数量，不限制已拥有饰品数量或继续购买。

卸下饰品只移除该饰品的主页展示，其他饰品保持不变；替换饰品通过先卸下、再装备完成。刷新或重新进入主页后恢复已保存的装扮。商品下架或删除后，已拥有物品仍可查看、装备和展示，购买时保存必要的商品信息。

在“我的装扮”中选中已装备饰品后，可以用鼠标或触摸拖动，并使用位置微调按钮或键盘调整；大小保持图片原始比例。画布为正方形，饰品的正方形包围盒完整保留在画布内。整体形象按比例完整显示，背景按比例铺满，必要时裁切。

层级提供“向上一层、向下一层、置顶、置底”。角色也是排序的固定参照，饰品可以移到角色后方；背景始终位于最底层，特效始终位于最顶层。编辑单件饰品时，位置、大小和层级一起保存，也可以取消；失败时保留草稿。其他设备移除了当前饰品或排序目标时，提示重新读取状态后再调整。

卸下饰品会保留位置和大小，再次装备时恢复并放到当前饰品最上方。切换整体形象保留饰品布局，由用户重新调整，不自动猜测头部或手部位置。

下雪、闪光等特效不能移动、缩放或调整层级。移除特效只取消当前佩戴，保留已购买的所有权；多个特效同时佩戴时按稳定顺序叠放。账户或系统开启减少动效时，特效改为静态展示。

### 我的奖励与兑现

文本奖励购买后进入“我的奖励”，显示名称、购买日期和“待兑现”状态。兑现前验证管理密码，确认后改为“已兑现”，显示兑现时间。兑现不再扣币或扣库存，重复点击不能重复兑现。

首版不做退货、转赠或审批。已经花掉的金币对应记录被删除，也不撤销已购买奖励。商品下架不移除待兑现奖励。

## 8. 留言板与声音

留言板是当前账户内的家庭留言，支持新增和删除文字留言，显示时间。无公共访问、回复、点赞或消息通知。空白留言不能发布；删除前确认，输入中的文字不能因其他区域刷新丢失。

背景音乐默认关闭，需要用户主动开启；音乐与操作音效分别控制。提供减少动效选项，并尊重系统减少动态效果设置。减少动效时保留文字和静态成功反馈，不影响功能。

## 9. 管理界面

### 账户与密码

配置姓名，修改登录密码和管理密码。保存成功后给出反馈，姓名即时用于所有展示区域。登录用户名与显示姓名明确区分，首版不增加用户名变更流程。

### 类别与项目

类别支持新增、改名、删除；一个类别下可有多个项目。删除非空类别前要求先移动或删除其项目，避免隐式批量删除。

项目字段为名称、图标、所属类别、金币数量、钻石数量、每日最多次数和可出现的星期。每日最多次数默认 1，须为正整数；货币奖励为非负整数；星期支持多选，至少选择一天。名称不能为空。

任务管理列表提供直接“开启”和“关闭”操作，保存成功后更新状态并显示反馈。列表默认隐藏已关闭任务，勾选“显示已关闭任务”后可查看并重新开启；筛选只影响当前页面展示。关闭任务后，今日任务和补录选项不再展示该任务，也不能为其新增打卡或补录，已有记录、统计和原奖励保留。重新开启后仍按星期安排及每日次数限制判断是否出现在今日任务中。

更改任务配置从后续新建记录起生效，不重算已有奖励。降低当天次数上限后，已有记录保留，但不再允许超额新增。删除项目使其停止出现在今日任务中，已有记录和统计保留。任务开启和关闭沿用成就的排期历史规则：当天起采用新状态，同一业务日多次调整采用当天最后配置，连续完成成绩据此重算。

### 打卡记录

按日期展示记录，支持新增、查看、修改和删除，并清楚显示所影响的日期。管理记录保留原金币、钻石奖励信息，供核对余额；普通界面隐藏已完成记录的分值不影响数据保存和奖励结算。可补录过去日期和今天，不可新增未来日期；新增须检查任务在该星期的安排与当日次数限制。补录按照创建时的任务配置生成奖励快照。

修改附件与文字不改奖励，不直接修改记录日期或项目。若需纠正日期或项目，采用删除旧记录后补录：删除扣回旧记录的原奖励，补录重新检查目标日期的星期安排、次数限制及非未来限制，并按当前项目配置生成新奖励。操作前须明确提示奖励可能重新计算，不能将该流程描述为保留原奖励的内容编辑。

已停用项目的历史记录仍可查看、修改内容与删除，但不再用其新增打卡。删除规则与普通界面一致，允许负余额。

### 商店配置

支持新增、编辑、删除商品，调整名称、类型、图标或素材、描述、金币价、钻石价、库存。价格须为非负整数；库存不得为负，支持不限量。编辑价格只影响后续购买，不修改历史购买记录。

已有购买记录的商品不允许直接改成另一商品类型，避免原有装扮与兑现规则发生变化；应新建商品并下架旧商品。删除商品保留既有所有权与购买快照。

## 11. 视觉与交互规范

采用卡通冒险游戏风格，围绕森林营地、小动物伙伴、任务卡与奖励商店组织界面。以明亮草绿、奶油白和暖黄为主。任务图标、金币和钻石使用彩色实心卡通 SVG，保持固定图形及颜色，不生成位图来替代这些图标；文字保持足够对比度，避免浅色字叠在复杂场景上。

主要按钮采用圆润轮廓和轻微立体感；插画、图标与装扮保持统一风格。仍使用“打卡”“月历”“统计”“商店”等清楚的功能名称，不用游戏术语替代用户需要理解的操作。精简欢迎语、宣传内容和重复说明，让任务、记录和操作优先进入视线。

整个应用以稍远距离也能阅读为目标：主要文字为 22–24 像素，标题为 32–40 像素，所有辅助文字和其他可见文字至少为 18 像素。手机不缩小字体，而通过纵向排列、换行和增加空间保持可读性。该要求覆盖主界面、月历、统计、商店、登录、管理页面及全部弹窗，不能只放大首页。

动效用于按钮按下、弹窗出现、成功打卡、金币入账和换装反馈。常驻场景动效应轻微，不遮挡内容、不要求等待动画结束才能继续操作。较长音频或音乐必须可暂停。

可交互区域适合触屏，按钮目标不小于 56 × 56 像素；键盘可操作，焦点可见。弹窗打开后焦点进入弹窗，关闭后返回触发位置。表单提供可见标签，错误出现在对应字段附近。信息不能只通过颜色传达。

## 13. 逻辑检查结论与后续事项

本次方案已补齐原需求中主要的闭环：删除与消费后的负余额、修改记录不重复发奖、任务配置与历史快照、月历和统计口径、永久装扮所有权、文本奖励兑现、库存变化、姓名展示及历史编辑权限。

正式实施按以下边界执行，完成状态以开发计划证据为准：

1. **账户初始化与密码恢复**：CLI 交互设置唯一账户与两种密码，忘记密码时通过 CLI 重置；网页仍可校验旧密码后修改。正式初始化不使用原型密码。
2. **部署与数据存储**：单实例、本地持久化磁盘和私有媒体；本次提供部署产物及模板并在本地验证，生产主机、HTTPS 地址和访问范围另行指定。本次不开发备份，也不设计跨设备同步。
3. **媒体约束**：图片、音频、文本及清理参数采用技术方案 §15 的已确认值。真实采集功能保留，验证使用自动化浏览器和真实媒体文件，不做真机兼容性验证。
4. **音乐与美术资产**：正式素材来源、使用权、音频文件和角色装扮素材规格。静态素材与模拟声音不代表最终内容已确定。
5. **历史任务规则**：首版补录采用创建时的任务配置；若未来需要按“过去当天的任务配置”补卡，须增加配置历史，并单独确认该范围。
6. **长时使用与跨日**：正式实现需在跨日、重新进入页面和多设备同时操作时重新核对日期、余额、库存及次数；这些不能由静态原型证明。

本轮不引入注册系统、多角色权限、审批、退款或复杂成长等级。

## 14. 成就与徽章

成就包含一段短文本和一张内置徽章。主界面在形象区下方、家庭留言上方展示已佩戴的徽章，点击可查看文本、条件及获得时间。“成就”页面展示已获得成就和未获得成就的进度，支持逐个佩戴、卸下。可以佩戴多个，徽章自动换行；新获得或重新获得时不自动佩戴。

详情显示统计范围内的具体类别或任务名称，已删除关联标明状态，普通用户无需进入管理页面即可查看。管理编辑遇到版本冲突时，最新配置与类别、任务选项一起刷新；全部成功后才能采用最新配置或确认覆盖，加载失败保留草稿并允许重试。

管理页面提供独立的成就配置。每个成就选择一种指标、一个目标值、统计范围，以及可选的时间窗口，不支持任意条件表达式。

| 指标 | 计数方式 |
| --- | --- |
| 累计打卡次数 | 每条有效记录计一次，同一天多次完成分别计数 |
| 累计打卡天数 | 按台北业务日期去重，同一天只计一天 |
| 连续完成 | 按任务实际安排的计划日计算，当日范围内每个应做任务各至少完成一次 |
| 累计金币 | 有效记录的原金币奖励之和，消费不减少累计量 |
| 累计钻石 | 有效记录的原钻石奖励之和，消费不减少累计量 |

范围支持全部任务、当前类别或指定一个或多个任务。范围内的记录合计统计。任务调整类别后，历史贡献随当前类别一起移动；删除任务则冻结删除前归属，保留有效历史记录、类别身份和排期依据。删除类别只隐藏配置入口，不清除历史身份；仍有未删除任务的类别不能删除。

时间窗口留空表示不限，填写 N 表示任意连续 N 个自然日内达到目标。进度展示历史上符合该窗口的最好成绩，不仅是最近 N 天。连续完成同样保留历史最佳：只在周一出现的任务，连续几个周一完成即可；没有应做任务的日期既不计数，也不中断。每日次数上限不是每日必须完成的次数。

排期调整前的日期按原排期计算，调整后按新排期计算；同一业务日多次调整采用当天最后配置。删除任务停止未来安排，保留删除当天及之前的历史义务，不能通过删除未完成任务补出历史连续成绩。

普通打卡、管理补录及已有有效历史记录均参与评估。补录仍按当前任务配置校验，不改变原补录入口的权限和次数规则。新增成就、调整条件及重新启用时立即判断历史是否达标；新获得时记录实际授予时间，不倒推历史日期。

删除打卡记录后重新计算：若其他记录或另一段历史窗口仍达标，成就保留；否则恢复为未获得并同时卸下。重新达标后更新获得时间，不恢复此前佩戴。任务配置删除本身不移除它的历史贡献。修改成就条件按新规则统一重算；文字和徽章同步更新。停用、删除成就配置停止新授予，已获得资格仍保留，但删除贡献记录后仍须重验。
