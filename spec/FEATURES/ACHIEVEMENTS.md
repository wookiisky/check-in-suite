# 成就与徽章

## 职责与呈现

成就把有效打卡事实转换成进度和资格。每项配置包含短文本、内置徽章、一个指标、目标值、统计范围和可选自然日窗口，不提供任意条件表达式。消费和钱包当前余额不作为成就进度来源。

成就页面显示已获得项目及未获得项目的进度。用户可以逐个佩戴、卸下多个徽章；营地在角色下方、家庭留言上方展示并自动换行。新获得或重新获得时都不自动佩戴。详情显示条件、具体类别或任务名称及授予时间，关联已删除时说明其状态。

## 指标与范围

| 指标 | 计算口径 |
| --- | --- |
| 打卡次数 | 每条有效记录计一次，同一天多次分别计数 |
| 打卡天数 | 按台北业务日期去重 |
| 连续完成 | 每个计划日内，范围中的应做任务各至少完成一次 |
| 累计金币 | 有效记录的原金币奖励之和 |
| 累计钻石 | 有效记录的原钻石奖励之和 |

范围可选全部任务、一个类别或指定任务集合。类别按任务当前归属判断，移动类别时历史贡献随任务移动。删除任务冻结删除前的类别引用，保留记录和排期；删除类别保留历史身份，仍含未删除任务时不能删除。

未指定窗口时计算全部有效历史；指定 N 天时，在任意连续 N 个自然日中寻找历史最好成绩，包含窗口两端。展示的是历史最佳，不局限于最近 N 天。计数、天数、原奖励和连续完成均使用该窗口语义。

## 连续完成与排期

连续完成按计划日计数，不要求每天都有任务。没有应做任务的日期既不增加进度，也不中断；计划日中遗漏任何应做任务会中断该段。每日次数上限只是可打卡次数，不要求全部用满。例如只安排周一的任务，连续几个周一完成就可构成连续成绩。

任务创建时保存初始排期，之后的开启、关闭和星期调整以台北业务日期保存。调整日前采用旧排期，当日起采用新排期；同日多次调整使用当天最后配置。删除任务从次日停止计划，保留删除当天及之前的义务，不能靠删除未完成任务补出历史连续成绩。

管理补录仍按[打卡专题](CHECKIN.md)中的当前任务规则校验，不改用历史排期限制补录。保存的有效完成记录也视为该日的实际出现；补录日期早于任务创建时，初始排期扩展到该日期。其他任务在历史日期的义务仍按其排期判断。

## 授予、失效与重新获得

普通打卡、管理补录和既有有效记录都参与计算。新增成就、调整条件或重新启用时立即检查历史事实；首次达标记录实际授予时间，不倒推为历史完成日。

删除打卡后重新计算。其他记录或另一段历史窗口仍达标时保留资格，否则变为未获得并同时卸下。重新达标记录新的授予时间，不恢复此前佩戴。删除任务配置本身不移除历史记录的贡献。

修改成就条件使用当前定义统一重算，不保存另一套旧获奖规则；文字与徽章更新同步展示。停用或删除配置后不再新授予，但已获得资格继续保留并随有效事实重验；失效后也不能在停用状态下重新获得。

## 提交与竞争

纯计算读取有效打卡、任务当前类别和排期历史，返回确定的进度。业务写事务保存资格变化：打卡新增、删除、任务归类或排期变更及成就规则变更，与资格失效和卸下一起提交；失败时整笔回滚。内容和附件编辑不改变指标。

列表与营地读取不补写资格，营地徽章与其他数据使用同一读取快照。这样读请求不会悄悄改变业务状态，也不会显示已经失效但尚未卸下的徽章。

管理创建沿用幂等请求，编辑采用版本检查和管理授权。发生冲突时同时取得最新成就、类别及任务选项，全部加载成功后才允许采用最新配置或重新确认覆盖；加载失败保留草稿。佩戴按单项绝对状态提交，可重复设置，不用“切换”请求推测最终状态。

徽章只能选择受控的徽章素材，使用不可覆盖的版本标识；资源与所有权规则见[商店专题](SHOP.md)，协议字段见[HTTP API](../SYSTEM/HTTP_API.md)。

## 验证边界

纯计算测试覆盖窗口、同日多次、无计划日、历史排期和删除任务；真实数据库测试覆盖资格变化与业务事务的一致性。页面测试检查解释、冲突草稿和佩戴结果，不把旧验收数量当作当前通过证据。测试选择见[测试指南](../ENGINEERING/TESTING.md)。
