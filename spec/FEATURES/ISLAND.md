# 营地建设与活动

## 职责与协作

营地提供全屏三维场景，让用户摆放已拥有物品并观看人物活动。渲染使用 Three.js、React Three Fiber 和实际 GLB。首页、外观编辑器与营地复用同一人物组装组件和已保存外观；不同视图持有独立骨架和播放器。打卡页以 HTML 展示成就文本和徽章，规则见 [成就](ACHIEVEMENTS.md)。

购买复用商店的订单、钱包和所有权，没有第二套扣款系统。活动只在当前页面表现，不产生离线收益，也不新增服务端执行记录。旧二维目录、自由配件、动物形象、背景特效、旧布局接口及房屋升级逻辑已退出；不提供旧人物或布局转换，数据库不兼容时严格拒绝启动。

静态摆件与可进入房屋按不同加工类型制作。房屋的门洞、剖切和实际地板支撑面属于必需专项；视觉范围、摆放占地和行走阻挡分别核对。候选及应用流程见[运行手册](../ENGINEERING/OPERATIONS.md#素材分类候选与应用)，具体检查边界见[测试指南](../ENGINEERING/TESTING.md)。

## 场景、相机与页面

免费海边始终可用，购买其他场景后增加永久可进入的独立空间。各场景分别保存房屋、物件、光照和版本；钱包、订单、人物外观和物品库存由各场景共用。在营地标题栏的场景选择中切换已解锁空间。每台设备只在本地记住当前目的地，切换不会改变其他设备的场景。新场景初始只有固定景观，可以暂时没有房屋。

场景以有限草地、沙滩和水域组成。前后端共用场景数据；地面绘制、完整占地判断和导航使用相同厘米坐标。远海与背景仅作视觉延伸，不扩大可摆放或可行走范围，水域当前不能保存物件。

相机采用固定俯仰的正交投影，提供四方向旋转、平移与缩放。鼠标、触摸、按钮和键盘经过同一相机或摆放计算；相机状态不写入布局。进入屋内时按房屋和浮层范围取景，只在空间切换时适配，不因活动状态刷新反复夺走用户镜头。

HTML 操作区独立于场景坐标。主导航、返回、设置、余额及今日打卡入口不随场景缩放；今日任务直接复用打卡快照与图标。余额规则见 [界面](INTERFACE.md)，打卡规则见 [打卡](CHECKIN.md)。进入页面重新读取当前任务与余额，不自行重算。

桌面布置面板在右侧，手机在底部。布置反馈、库存和微调位于同一滚动区域，头部和保存取消入口保持可用；冲突提示不能浮盖物品按钮。查看室内或选中物品时可收起库存，为场景留出空间；微调、保存和取消仍可操作。相机适配计入实际工具栏与面板占用。返回、切换场景或通过标题栏离开共用离开流程：未保存时可保存后离开、放弃或继续编辑；失败不导航。

## 物品、库存与厘米布局

主屋、书桌与运动区免费进入初始库存，其余陈设通过订单取得。商品是报价，物品定义提供稳定身份、实际 GLB、缩略图、占地、行走阻挡和可选交互。家具和户外物件使用实际模型生成的静态缩略图，商店卡片不创建独立 Canvas。

新增素材先保留完整物件库，再从中选择适合海边营地和家庭生活的代表款上架，同种物件尽量不重复。只接入可以独立作为摆设的完整物件，不接入单面墙、屋顶、门框、地板和道路拼片等搭建零件。完整建筑、家具、植物、车辆和非人形模型只按目录声明的静态摆设能力使用，不因为有模型就增加拼装、驾驶或战斗行为。摆设在整理时统一地面锚点，并依据实际交付几何登记完整占地；布局目前只提供地面位置，不支持把小件挂到墙面或放上桌面。

库存支持名称、来源、素材包与类别筛选，并分批显示缩略图。筛选与分批只改变可见列表；完整实例所有权和布局保存继续使用原始快照，已经摆放的物件不会因当前筛选不匹配而消失或被收回。不同实例仍按购买身份区分。

每笔可重复购买产生独立实例，同一实例在全部场景中只能占用一处；可以移动或收起，停用商品不撤销所有权。每个场景最多一栋主屋，也允许没有房屋；无房时只能使用室外空间。房屋朝向固定，位置可以移动，撤下后保留所有权。房型与场景分别配置，房型不绑定某个场景；换房预览按目标房型的实际几何校验，容不下的室内家具保留为待处理冲突，不自动清空或搬动。光照单独选择。书桌可放室内外，其他家具与户外物件按各自定义允许空间，不能从名称推断能力。

`GET /island/scenes` 返回正式场景与家庭的永久资格；`GET /island/layout` 省略场景参数时继续读取海边，指定 `scene_key` 时读取目标空间，`PUT` 按请求中的场景身份保存。未拥有场景不能读写布局。每个场景使用独立版本。室外使用世界位置，室内使用主屋局部位置；两个地面坐标统一为整数厘米，朝向为零到三的四分之一圈。读取在同一数据库快照内取得版本、完整库存、物件目录和场景。空状态返回该场景默认布局，不在读取时写库。原有已保存三维布局迁移时保留摆放顺序、版本、光照及实例身份；尚未保存的海边默认摆设也参与跨场景占用判断。

保存一次提交完整布局和预期版本。服务端在事务内复核会话、版本、实例所有权、重复实例、允许空间、旋转、完整占地、摆放互斥及通路；任何验证或提交失败都保持原版本和布局。库存读取全部订单，不以商店分页作为完整库存，并标明实例所在场景。搬运采用先在原场景收起并保存，再到目标场景摆放并保存；服务端事务与实例唯一约束保证两台设备同时争用时最多一处成功，失败不改变任一场景。

## 地形、墙体与通路

允许地形按完整占地覆盖判断，草地和沙滩可共同覆盖。前后端使用同一几何案例，采用区域并集计算；凹岸缺口不能因中心或四角在岸上而放行，同类区域的重叠也不能掩盖空缺。场景之外不视为可摆放区域，边界接触不算物件重叠。固定树木、树篱及景物的模型、位置和阻挡统一配置，摆放验证与人物导航使用同一数据；湖水不可行走或摆放。

摆放占地、行走阻挡与交互位置分别声明。仅双方均声明摆放互斥时禁止重叠；例如运动区可与球共存，球不阻挡人物行走，但不能塞进实体家具。没有动画或交互的静态陈设也是完整能力，不要求每件物品提供活动。

主屋占地包含墙厚和屋顶外沿，室内地板范围独立定义。外墙、南门洞、卫生间隔墙和门廊由共享场景数据提供。家具完整占地不能跨实体墙；行走阻挡不能堵住内外门廊。通路范围用于碰撞校验，人物脚下高度另按实际模型的楼板、平台和台阶确定。新房型从实际 `floor` 节点提取朝上的三角面，使用房屋局部厘米坐标、去重顶点和索引保存；室外命中多个支撑面时取最高插值高度，包含门廊侧边和倒角。室内仍使用地板高度；旧房型没有支撑面时沿用入口高度曲线，不能把整段通路当成斜坡。客厅、睡眠与厨房家具不强制分区，卫生间仍属于同一室内局部坐标空间。

床、餐桌椅、沙发、茶几、电视、柜子、冰箱、操作台、马桶、洗漱台和淋浴间提供独立静态模型，不因此新增睡觉、看电视或洗浴行为。初始不赠送这些家具，购买后再布置。

## 草稿、冲突与结果未知

编辑仅改变本地草稿，取消不写库。草稿、读取代次和原保存请求按客户端及场景身份分别保留；切场景也遵循保存后离开、放弃或继续编辑，保存失败和结果未知不会丢失原场景草稿。版本冲突保留草稿，读取最新状态后明确核对才能继续保存；读取只取代已保存基线，不静默覆盖正在编辑的布局。离开没有修改的编辑状态会清理干净草稿，重进不会误报冲突。其他设备将同一实例放到别处时，当前页面保留草稿并明确提示库存冲突；读取最新库存和布局后，即使本场景版本未变，也须核对草稿。仍在草稿中的冲突实例可以选中收起，但不能继续移动、旋转或添加到当前位置；读取失败保留重试入口，不自动重发保存。

网络中断等情况可能发生在服务端提交之后。客户端保留原请求与草稿，禁止修改、取消或离开。同一客户端卸载重挂后继续核对；读回原版本时只能显式重发原预期版本请求，不能提高版本后覆盖。版本推进且完整布局相同才确认成功，内容不同则进入核对。取消和迟到的 GET 不能覆盖较新的保存。

活动资格通过独立 `GET /island/activity-access` 读取，不读取布局或库存，也不覆盖编辑草稿。其版本和生命周期与布局分开，不能用保存布局来刷新权限。

## 角色活动与屋内展示

人物可自主或手动散步、休息、阅读、运动、玩球。按钮、物件点击和自主选择共用同一执行器；散步与休息始终开放，其余活动同时要求物件能力、可达目标及当天资格。业务活动身份固定为 `read/run/ball`，与动作片段名称分开。

导航依据身体半径、有限陆地、墙体、门洞和家具行走阻挡寻找路径，避免斜向穿墙。网格随主屋位置锚定，移动房屋后仍能通过门洞。角色先到可达的靠近点，再进入独立座姿根位置，结束或撤销后返回靠近点；不能为了表演而把桌子或墙设为可穿过。

阅读播放实际坐姿，使用精确骨骼矩阵挂接书本；运动播放离线转换后的 Mixamo 动作；玩球使用与踢球触点同步的轨迹，并校验完整轨迹的地形和障碍。书和球是活动道具，不增加装备槽。资源全部准备前冻结对应表演时间，失败保留 HTML 提示与重试。

人物进入房屋后隐藏屋顶和相机前方墙面，离开后恢复外观。布置可主动查看室内，不切换页面。四个相机方向均按共享墙体判断剖切，家具与人物使用真实深度遮挡。

## 打卡解锁

任务可关联阅读、运动和玩球，同一活动可关联多个任务。今天任一个关联任务有一条有效打卡即可使用，不要求达到次数上限；没有关联任务时保持开放。关联按任务身份，不根据名称推测，也不消费记录或额外发奖。

资格在同一读取事务内复核会话，只取一次时钟，按 `Asia/Taipei` 日期计算，下个午夜失效。删除最后一条满足条件的今日打卡后，下次刷新重新锁定；补录过去不影响今天。停用或调整排期不抹去已有有效打卡贡献；未打卡的停用任务仍保留关联。删除任务解除关联，修改关联影响后续计算。

关联配置沿用管理授权、任务版本与幂等事务：新建省略表示空，更新省略保留，显式空数组清除。进入页面、恢复前台和跨日时读取资格，不轮询或推送。刷新期间或失败后撤销受限旧资格，保留无条件活动，并提供重试。

客户端用校准时间判断期限，拒绝迟到的昨日响应。每次请求活动和推进角色都复核资格；暂停、隐藏或减少动效也不能延长期限，失效活动立即停止。锁定入口展示关联任务并可前往打卡，跳转仍遵循草稿离开规则。

## 动效、资源与验证边界

人物位置与动作逐帧更新留在 Canvas 内，React 只接收离散状态。编辑期间冻结人物与导航重建，保存或取消后按最终布局恢复；目标移动、收起或资格失效会停止活动。隐藏、暂停和减少动效时不累计运动时间，恢复后丢弃首帧间隔。海面材质变化不移动实际岸线。

源包、Blender 工程和原始 FBX 位于本地 `.local/3d-sources/`，正式安装仅使用整理后 GLB、PNG 与元数据。许可和出处分别记录，不能把 Mixamo 动作当作 KayKit 的 CC0。`/3d-preview.html`、`/character-preview.html`、`/island-3d.html` 保留为真实资源验证入口，正式用户从主应用进入营地。

服务与真实数据库测试证明所有权、完整占地、并发版本和事务原子性；组件测试证明草稿与请求竞争；浏览器检查实际 shader、坐姿与书本、四向剖切、手机控件及失败恢复。测试入口不表示本轮已执行，设备和性能证据限制见 [测试指南](../ENGINEERING/TESTING.md)。
