# 小岛建设与活动

## 职责与协作

小岛提供独立全屏的二维卡通场景，让用户摆放已拥有物品并观看角色活动。场景采用固定斜俯视投影，以地面、物体侧面、阴影和遮挡呈现空间，不提供自由旋转摄像机。渲染使用 React 与 SVG，布局、相机、角色活动和绘制分开管理。

小岛复用 [商店](SHOP.md) 的购买、钱包和订单，没有第二套扣款系统。人物形象与固定穿戴共用画像组件；其他整体形象沿用自身素材。活动是当前页面中的表现，不产生离线收益，也不新增服务端活动执行记录。

## 页面与导航

进入小岛后占满可用视口，隐藏普通页头和留白。左上角返回来源页，右上角提供布置、商店和设置入口，右下角展示角色状态、活动及暂停控件。界面使用页面坐标，字体和操作区域不随场景缩放。

余额常驻顶部；左侧今日打卡区复用营地快照中的任务及图标，不维护另一套筛选逻辑。任务入口只显示图标，名称保留在提示和可访问标签中。点击进入营地，由打卡模块处理提交；进入小岛、购物或打卡后返回时读取当前任务与余额。

打卡区首次进入展开，进入布置时收起，也可手动展开；项目较多时在区域内滚动。桌面布置面板在右侧，手机在底部，物品列表独立滚动，保存和取消保持可见。相机依据浮层之外的可见区域适配，避免房屋或角色被操作面板遮挡。

返回、进入商店和进入营地共用离开流程。有未保存布局时，可保存后离开、放弃或继续编辑；保存失败不导航。声音设置使用弹层，共用原有声音实例，通用界面与声音规则见 [界面](INTERFACE.md)。

## 物品、库存与布局

基础房屋、书桌、运动区域和默认环境免费。目录为物品定义稳定身份、显示模型、占地、摆放区域、购买规则和可选活动。管理页维护报价和上架状态，不提供任意编辑动画或互动能力的表单。

展示、动画和互动能力可以分别增加；没有动画或互动的静态物品也是完整状态。目录没有声明活动时不显示互动入口。已购实例按稳定身份取得当前能力，订单的成交名称和价格等快照不因此变化。

可重复商品的每笔订单产生一个独立摆放实例，同一实例只能摆放一次；可以移动或收起。双用途物品可同时用于画像和小岛，两处装备关系独立保存；岛屿专用品不进入画像衣柜。下架或删除商品不清除已购实例。

房屋和环境必须各保留一个，位置和朝向受各自定义限制。室内外位置分别保存，物品不能超出所在区域；服务端校验真实所有权、重复实例、旋转、场景边界和门口通路。不是所有物品都可移动，也不是所有物品都能放进室内。

布局保存地面坐标和物品朝向，相机的平移缩放不改动物品位置。浏览模式拖动场景，布置模式选择和移动物品；触屏提供平移及双指缩放，同时保留按钮和键盘操作。室内局部坐标使用房屋投影与逆变换，保证缩放后的拖动仍落在正确位置。

## 布局保存与冲突

布局读取在同一数据库快照中取得版本、完整库存、目录和当天活动资格。库存从全部已拥有订单读取，不能受商店分页影响。

保存携带预期版本，服务端在同一事务内复核会话、版本和所有布局约束，再原子写入并递增版本。其他页面已保存时返回版本冲突，当前页面保留草稿，用户读取最新状态后核对；未确认的结果不能显示为已保存。

活动资格刷新仅更新资格，不能覆盖当前布局或布置草稿。保存响应虽同时携带资格，也必须遵循活动期限判断。通用重试和版本语义见 [HTTP 协议](../SYSTEM/HTTP_API.md)。

## 角色活动与屋内展示

角色可自主散步、休息、阅读、运动和玩球，也可响应按钮或场景物品点击。自主与手动活动共用条件和执行逻辑，角色先移动到目标，再持续表现对应动作。散步和休息始终可用。

房屋进入与离开都发生在同一场景：角色进入后隐藏屋顶和前墙，显示室内；离开后恢复外观。布置时可主动查看室内，无需切换页面。房屋占地、室内坐标、门口和绘制比例共同由当前目录与几何实现决定。

狐狸、兔子使用肢体动画；人物和其他整体形象使用组合或图片，通过整体起伏、倾斜及活动道具表达动作。当前装备变化应同时反映在营地与小岛，人物发型和衣物不得在两个场景分别维护。小岛中的穿戴随整个角色动作和镜像变换，不进入可摆放物件目录。

## 打卡解锁

任务配置可以关联阅读、运动和玩球，同一活动可以关联多个任务。当天任意一个关联任务存在一条有效打卡，即可使用该活动，不要求达到每日次数上限。关联使用任务身份，不能根据名称推测。

没有关联任务的活动保持开放。阅读资格对所有声明阅读能力的物品生效，物品能力与当天资格是两个独立条件。锁定入口可查看关联任务并返回营地，跳转仍遵循草稿离开规则。

资格按 `Asia/Taipei` 日期动态计算，到下一个午夜失效，不另存永久解锁标记。删除最后一条满足条件的有效打卡后，下次刷新重新锁定；补录过去日期不影响今天。活动不会消费打卡记录或额外发奖。

停用或调整排期不抹去当天已有有效打卡的贡献；未打卡的停用任务仍保留活动关联。删除任务解除其关联，若活动已无其他关联则开放。修改关联立即影响后续资格计算。打卡的新增与纠正规则见 [打卡](CHECKIN.md)。

任务关联写入沿用管理授权、任务版本和幂等事务：新建省略关联表示空，更新省略则保留，显式空数组清除。关联关系由追加迁移建立，迁移执行与历史校验要求见 [存储](../SYSTEM/STORAGE.md)。

进入页面、恢复前台和跨日时读取资格，不通过轮询或推送同步其他页面。刷新期间或失败后，暂停使用需要打卡的旧资格并允许重试，散步、休息及无任务条件的自由活动仍可用。

客户端用校准时间判断期限，取消被新请求取代的读取，拒绝迟到的昨日资格。每次发起活动和推进角色状态时复核期限；暂停或减少动效也不能延长资格，失效目标须停止。刷新过程保留布置草稿。

## 动效生命周期

物件动画由目录声明驱动，风车扇叶、喷泉水流、秋千座椅、灯光和花茎等局部运动，底座、支架及阴影保持固定；缩放与镜像作用于整个物件。没有动画声明时显示静态模型，原静态素材继续用于商店缩略图。

暂停或页面隐藏时，角色姿势与物件动画一起冻结；恢复后继续，不补算后台时间。布置或账户、系统要求减少动效时保留静态画面和可理解的活动反馈。动作不会改变物品能力、布局或购买历史。

## 验证边界

重点检查真实所有权、重复实例、布局版本冲突和非法位置；资格检查覆盖当天有效打卡、停用与删除、午夜、设备时钟偏移、迟到响应和草稿保留。界面检查覆盖移动、缩放、离开处理、角色进出屋及动效暂停恢复。

元数据仅列测试入口，不代表本轮执行结果。手机尺寸 WebKit 不等于真机触摸验证，模拟页面可见性事件不证明操作系统后台行为；相关限制见 [测试指南](../ENGINEERING/TESTING.md)。
