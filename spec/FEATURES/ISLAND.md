# 营地建设与活动

## 职责与协作

营地提供独立全屏的二维卡通场景，让用户摆放已拥有物品并观看角色活动。场景采用固定斜俯视投影，以地面、物体侧面、阴影和遮挡呈现空间，不提供自由旋转摄像机。渲染使用 React 与 SVG，布局、相机、角色活动和绘制分开管理。

营地复用 [商店](SHOP.md) 的购买、钱包和订单，没有第二套扣款系统。人物形象与固定穿戴共用画像组件；其他整体形象沿用自身素材。活动是当前页面中的表现，不产生离线收益，也不新增服务端活动执行记录。

## 整体场景与地形

默认场景为海边营地，草坪经过沙滩连接大海，陆地延伸到画面边缘，顶部保留天空。进入场景或恢复视图后，在不含天空和操作浮层的可见区域内，草坪与沙滩约占六成，海面约占四成；桌面与手机分别适配。这个比例是默认构图目标，平移、缩放或展开布置面板后不强制维持。

海边美术分四层：天空有太阳、云、飞鸟，地平线上有远岛和帆船；海面由远及近逐渐变浅，有波光、浅水带、岸浪、礁石和浮标；沙滩起伏宽窄不一，有湿沙带、贝壳、海星、遮阳伞和沙堡；草坪略高于沙滩，有明暗草斑、草叶花朵、灌木和椰子树。这些装饰都不是可摆放物品，不参与地形查询。椰子树、遮阳伞等高大装饰只放在旧室外活动范围的两侧或后方，因为地面层始终画在物件和角色下面，放在前方会出现错误遮挡。

整体场景使用有明确类型的定义，集中提供地形和默认取景；场景绘制与角色、物件分开。以后可通过统一入口替换完整场景，沿用既有物品布局和角色活动。本次只有海边这一种正式场景，不提供尚无其他选项的切换入口。目录中的白天、黄昏是环境叠加，与海边、森林等整体场景身份分开。

草地、沙滩和水域以同一世界坐标中的有限区域定义。绘图与地形查询共用区域数据，数据与范围判断不依赖 React。不同地形的内部不能重叠，只能共边；同类区域可以相交并共同组成可用范围。天空和云位于独立背景层；海面、沙滩、草坪及以后的水中物件共享地面相机变换。海浪的位移只改变画面，不改变实际岸线和水域边界。

当前室外物品的完整占地仍限于原有地面坐标范围，角色活动和出生范围也继续沿用现有契约。新场景将这些位置完整保留在草地或沙滩上，不迁移实例身份、物品坐标、室内外区域或布局版本。场景延伸出来的陆地与海面不因此成为当前物品可保存的新位置。

地形查询区分草地、沙滩、水域和场景之外，并可判断物品的完整占地是否都位于允许区域。跨岸、凹形岸线以及超出有限场景的情况不能只按中心点或四角放行；草地与沙滩可以共同组成允许区域。远处铺满画面的海水只是视觉延伸，不能将所有陆地之外的位置视为可布置水域。

这层坐标与范围判断为以后在水里布置和游动的鱼提供基础。本次没有鱼商品、游动行为、水域实例保存或相关接口扩展；以后增加这些能力时，服务端还需复用相同地形规则并校验完整占地，游动也应限制整个物件的范围。当前不能保存水域物件，不能以视觉上有水推断已经支持该能力。

## 页面与导航

进入营地后占满可用视口，隐藏普通页头和留白。左上角返回来源页，右上角提供布置、商店和设置入口，右下角展示角色状态、活动及暂停控件。界面使用页面坐标，字体和操作区域不随场景缩放。

余额常驻顶部；左侧今日打卡区复用打卡快照中的任务及图标，不维护另一套筛选逻辑。任务入口只显示图标，名称保留在提示和可访问标签中。点击进入每日打卡页，由打卡模块处理提交；进入场景、购物或打卡后返回时读取当前任务与余额。

打卡区首次进入展开，进入布置时收起，也可手动展开；项目较多时在区域内滚动。桌面布置面板在右侧，手机在底部，物品列表独立滚动，保存和取消保持可见。相机依据浮层之外的可见区域适配，避免房屋或角色被操作面板遮挡。

手机查看室内或加入室内家具时收起物品列表，为完整房屋留出空间；选中物品后仍可用底部方向按钮微调，也可重新展开库存。室内取景使用房屋实际范围，并计入顶部缩放按钮和底部操作栏的高度。

返回、进入商店和进入每日打卡页共用离开流程。有未保存布局时，可保存后离开、放弃或继续编辑；保存失败不导航。声音设置使用弹层，共用原有声音实例，通用界面与声音规则见 [界面](INTERFACE.md)。

## 物品、库存与布局

基础房屋、书桌、运动区域和默认环境免费。目录为物品定义稳定身份、显示模型、占地、摆放区域、购买规则和可选活动。管理页维护报价和上架状态，不提供任意编辑动画或互动能力的表单。

展示、动画和互动能力可以分别增加；没有动画或互动的静态物品也是完整状态。目录没有声明活动时不显示互动入口。已购实例按稳定身份取得当前能力，订单的成交名称和价格等快照不因此变化。

可重复商品的每笔订单产生一个独立摆放实例，同一实例只能摆放一次；可以移动或收起。双用途物品可同时用于画像和营地，两处装备关系独立保存；场景专用品不进入画像衣柜。下架或删除商品不清除已购实例。

房屋和环境必须各保留一个，位置和朝向受各自定义限制。室内外位置分别保存，物品不能超出所在区域；服务端校验真实所有权、重复实例、旋转、场景边界和门口通路。不是所有物品都可移动，也不是所有物品都能放进室内。

布局保存地面坐标和物品朝向，相机的平移缩放不改动物品位置。浏览模式拖动场景，布置模式选择和移动物品；触屏提供平移及双指缩放，同时保留按钮和键盘操作。室内局部坐标使用房屋投影与逆变换，保证缩放后的拖动仍落在正确位置。

## 布局保存与冲突

布局读取在同一数据库快照中取得版本、完整库存、目录和当天活动资格。库存从全部已拥有订单读取，不能受商店分页影响。

保存携带预期版本，服务端在同一事务内复核会话、版本和所有布局约束，再原子写入并递增版本。其他页面已保存时返回版本冲突，当前页面保留草稿，用户读取最新状态后核对；未确认的结果不能显示为已保存。

活动资格刷新仅更新资格，不能覆盖当前布局或布置草稿。保存响应虽同时携带资格，也必须遵循活动期限判断。通用重试和版本语义见 [HTTP 协议](../SYSTEM/HTTP_API.md)。

## 角色活动与屋内展示

角色可自主散步、休息、阅读、运动和玩球，也可响应按钮或场景物品点击。自主与手动活动共用条件和执行逻辑，角色先移动到目标，再持续表现对应动作。散步和休息始终可用。

房屋进入与离开都发生在同一场景：角色进入后隐藏屋顶和前墙，显示室内；离开后恢复外观。布置时可主动查看室内，无需切换页面。房屋占地、室内坐标、门口和绘制比例共同由当前目录与几何实现决定。

基础房屋与暖红屋顶小屋提供相同的家庭空间，更换房屋不缩减室内容量。客厅、睡眠区和厨房共用开放区域，以地板和家具区分；卫生间有固定隔墙与门洞，仍属于同一个室内坐标区域。房屋范围、隔墙、入口和通道由共享房屋配置提供，前后端均按家具完整占地检查，角色行走也避开隔墙。家具不能跨墙或堵住入口，但不根据家具用途强制其所在分区。

房屋主体采用横向舒展的长方形，凸窗、入口木质门廊和错落屋檐改变外部轮廓。窗帘、壁灯、窗台花箱和入口脚垫属于固定建筑美术，不生成库存物品，也不增加可摆放的侧厅或平台。室外占地包含附属结构的余量，室内可用面积另由房屋配置定义；相机与缩略图为完整建筑外沿留白，家具保留原有尺寸。

床、餐桌、餐椅、沙发、茶几、电视机、柜子、电冰箱、厨房操作台、马桶、洗漱台和淋浴间提供独立素材及可重复购买的商品，只能摆在室内。初始不赠送这些家具；购买后通过布置放入房屋。它们本轮只提供静态展示，不额外声明睡觉、看电视或洗浴活动。素材的透明留白、地面锚点和实际占地共同决定显示比例；转向时交换长宽的家具通过水平镜像保持固定视角下的落地关系。

家具在场景中复用内置 SVG 的实际图形，透明留白与阴影不参与点击，避免遮住相邻物品。卫生间隔墙按地面深度分段排列，与家具和角色共同决定前后遮挡；素材缩略图仍使用同一份 SVG 文件。

房屋扩建在服务启动时按记录的房屋版本执行事务升级，每个版本只处理一次。首次扩建前的布局和已完成上一版扩建的布局，分别按对应旧占地判断本次新增的冲突。优先保留原位置；只处理扩建新产生的房屋越界、覆盖或房门冲突，必要时将受影响物件移到最近可放置的位置，仍放不下则收回库存，所有权不变。不追溯修正历史已有的物件重叠，室内家具保留原有局部坐标。升级与布局版本递增、调整数量一起提交，尚未确认的调整数量继续累计，页面显示调整提示，下一次成功保存布局后清除提示。未保存过布局的账户继续使用默认布局。

狐狸、兔子使用肢体动画；人物和其他整体形象使用组合或图片，通过整体起伏、倾斜及活动道具表达动作。当前装备变化应同时反映在每日打卡页与营地场景，人物发型和衣物不得在两处分别维护。营地中的穿戴随整个角色动作和镜像变换，不进入可摆放物件目录。

## 打卡解锁

任务配置可以关联阅读、运动和玩球，同一活动可以关联多个任务。当天任意一个关联任务存在一条有效打卡，即可使用该活动，不要求达到每日次数上限。关联使用任务身份，不能根据名称推测。

没有关联任务的活动保持开放。阅读资格对所有声明阅读能力的物品生效，物品能力与当天资格是两个独立条件。锁定入口可查看关联任务并返回每日打卡页，跳转仍遵循草稿离开规则。

资格按 `Asia/Taipei` 日期动态计算，到下一个午夜失效，不另存永久解锁标记。删除最后一条满足条件的有效打卡后，下次刷新重新锁定；补录过去日期不影响今天。活动不会消费打卡记录或额外发奖。

停用或调整排期不抹去当天已有有效打卡的贡献；未打卡的停用任务仍保留活动关联。删除任务解除其关联，若活动已无其他关联则开放。修改关联立即影响后续资格计算。打卡的新增与纠正规则见 [打卡](CHECKIN.md)。

任务关联写入沿用管理授权、任务版本和幂等事务：新建省略关联表示空，更新省略则保留，显式空数组清除。关联关系由追加迁移建立，迁移执行与历史校验要求见 [存储](../SYSTEM/STORAGE.md)。

进入页面、恢复前台和跨日时读取资格，不通过轮询或推送同步其他页面。刷新期间或失败后，暂停使用需要打卡的旧资格并允许重试，散步、休息及无任务条件的自由活动仍可用。

客户端用校准时间判断期限，取消被新请求取代的读取，拒绝迟到的昨日资格。每次发起活动和推进角色状态时复核期限；暂停或减少动效也不能延长资格，失效目标须停止。刷新过程保留布置草稿。

## 动效生命周期

物件动画由目录声明驱动，风车扇叶、喷泉水流、秋千座椅、灯光和花茎等局部运动，底座、支架及阴影保持固定；缩放与镜像作用于整个物件。没有动画声明时显示静态模型，原静态素材继续用于商店缩略图。

海面波纹缓慢流动，波光闪烁，岸边浪花轻柔往复，浮标和帆船轻轻起伏，椰子树冠微微摆动，天空中的云和飞鸟缓慢飘动。场景装饰不接收指针事件，不遮挡物件的选择与拖放。

暂停或页面隐藏时，角色姿势、物件动画、海水和云一起冻结；恢复后继续，不补算后台时间。布置或账户、系统要求减少动效时保留静态画面和可理解的活动反馈。动作不会改变物品能力、布局或购买历史。

## 验证边界

重点检查真实所有权、重复实例、布局版本冲突和非法位置；资格检查覆盖当天有效打卡、停用与删除、午夜、设备时钟偏移、迟到响应和草稿保留。地形检查覆盖完整占地、跨岸、凹岸、允许区域的组合、场景外位置，以及原布局完整位于岸上；替换测试场景后，地形、背景和默认取景应一同切换，布局数据保持不变。界面检查覆盖默认构图、移动、缩放、离开处理、角色进出屋，以及海水、云和物件动效的推进、暂停、恢复和减少动效。

元数据仅列测试入口，不代表本轮执行结果。手机尺寸 WebKit 不等于真机触摸验证，模拟页面可见性事件不证明操作系统后台行为；相关限制见 [测试指南](../ENGINEERING/TESTING.md)。
