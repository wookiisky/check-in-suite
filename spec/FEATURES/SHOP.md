# 商店、装扮与奖励

## 职责与所有权

商店把当前可用金币和钻石兑换为装扮、营地物品或家庭约定的奖励。账户余额代表可购买数量，不等于累计获得数量；后者用于统计和成就。价格、库存、上架状态由管理页维护，素材与能力由受控资源目录定义。

商品是当前报价，订单是成交快照。订单保存购买时的名称、类型、素材、说明和价格；下架、删除商品或删除原打卡记录，都不撤销已取得的所有权。首版不提供退货、转赠或审批。打卡回收与负余额规则见 [打卡](CHECKIN.md)，事务与流水一致性见 [存储](../SYSTEM/STORAGE.md)。

## 购买与失败恢复

商品、我的装扮、小岛物品与奖励兑换卡片统一将名称居中放在大图上方，标题和价格保持大字，不堆叠说明文字。商品卡片底部左侧的购买按钮只展示金币、钻石图标及价格，不展示购买文字；不需要钻石时隐藏钻石。右侧单独展示已有图标与数量，零数量仍显示。按钮的无障碍说明包含价格及不可购买的原因，购买条件不随布局变化。

确认框展示商品、两种价格和购买后余额。两项价格都为零表示免费，两项都非零则同时支付；有限库存为零时售罄，不限量与零库存不同。

一次购买在同一事务内核对会话、幂等结果、商品版本、钱包版本、库存及重复购买资格，随后写订单、双币流水、钱包、库存和成功回执。任何一步失败都不能留下部分扣款或部分订单。免费购买也保存订单和零金额流水。

两种余额都必须满足 `余额 >= 对应价格`，因此任一种余额为负时，即使该币价格为零也不能购买。商品或钱包在确认后变化时，重新读取并让用户再次确认；结果未知时沿用原请求恢复，规则见 [HTTP 协议](../SYSTEM/HTTP_API.md)。

普通永久商品不能重复购买；文本奖励允许重复，每次产生独立待兑现订单。营地物品是否允许重复由物品定义决定，每次购买仍只取得一个实例，其摆放规则见 [营地](ISLAND.md)。

购买成功不自动装备，装扮操作也不再次收费。已拥有列表按订单分页，切换筛选时不能沿用另一筛选的游标；营地所有权读取全部订单，不以当前商店页作为完整库存。

## 角色与装备

营地与衣柜展示同一份已保存装备。称号、整体形象、背景各有一个槽位；饰品和特效允许多件。背景位于画布底部，角色与自由饰品参与前后排序，特效固定覆盖画布。姓名和币种的通用呈现见 [界面](INTERFACE.md)。

当前角色模型提供免费男孩、女孩基础形象，以及可购买的整体形象。选择免费基础形象会清除已选整体形象，但保留其他装备槽位。默认基础人物由素材目录定义，人物发型不再通过复制完整人物图片来切换。

固定穿戴分为发型、上装、下装和鞋子四个独立槽位，每槽最多一件。固定穿戴商品仍使用饰品商品类型，由素材的槽位属性决定装备位置；它们不计入自由饰品的十件上限，也不能调用自由饰品的移动、缩放或排序接口。

基础人物采用身体和双腿清楚可见的全身比例，给上装、下装和鞋留出可辨识的展示区域。男孩、女孩共用身体轮廓、头部尺寸、肩线、腰线和脚底位置，通过脸部细节区分，使同一件发型或服装可以直接复用，不需要按性别分别制作。

男孩、女孩共用同一套穿戴组合，发型和服装不限制性别。未选择穿戴或卸下时，恢复对应人物的默认发型和基础衣物；发型的前后层由同一件商品决定，后发层不能独立购买或装备。人物组合按固定顺序绘制，画像与营地共用组件，切换基础人物不丢失购买和穿戴状态。

动物等整体形象继续使用完整素材，暂不显示人物穿戴层；切换回人物后恢复原有穿戴。整体形象和固定穿戴都不自动移动用户保存的自由饰品。

服务端只更新本次指定的单一槽位，并验证订单已拥有且类型或穿戴槽位匹配。不同槽位互不覆盖，同槽位以后提交为准；装备不递增账户资料版本。背景为空时恢复默认背景，称号为空时不展示称号。

## 自由饰品与特效

自由饰品最多同时装备十件，同一订单不能重复计数；数量限制不影响继续购买和持有。数量检查和装备写入在同一事务中完成，达到上限时保留原有装备。重复装备或重复卸下按目标状态成功返回，操作不影响其他饰品。

饰品使用正方形画布中的归一化中心坐标和包围盒尺寸。图片保持原比例，整个包围盒必须留在画布内；手机和桌面由同一坐标得到相同布局。可用鼠标、触摸、微调按钮和键盘调整，角色是固定的排序参照，饰品可以移到角色后方。

编辑时在本地预览，保存一次提交选中饰品的位置、大小和相对排序意图。服务端据此重新排列层级，不接受整套布局覆盖；其他饰品的位置和大小不变。重复保存同一排序意图不能继续向前或向后移动。

保存失败保留草稿。选中饰品或排序目标已被卸下时，返回装备已变化，由用户读取当前状态后再调整；切换选中对象或离开时先处理未保存修改。卸下只移除装备关系，保留位置和大小；再次装备恢复位置与大小，并放在当前饰品最上层。

特效可同时佩戴多个，按稳定顺序叠放，不占饰品额度，也不能移动、缩放或调层。移除特效仅取消佩戴；账户或系统要求减少动效时，使用对应静态版本。

## 奖励兑现

文本奖励购买后为待兑现，卡片展示名称、大图与兑现按钮（已兑现后显示已兑现状态）。每次兑现都必须重新输入管理密码，即使管理页已解锁也不能跳过；此次密码验证只授权本次兑现，不解锁管理页。

服务端先校验密码，再在事务内复核凭据版本、会话和奖励类型，将待兑现条件更新为已兑现并记录时间。已兑现订单返回当前状态，不再次扣币、扣库存或产生兑现副作用。凭据撤销边界见 [账户](ACCOUNT.md)。

## 素材与兼容边界

商品素材来自内置目录，不提供上传入口。内部人物组合层使用 `character-part` 类型，不出现在可选素材列表或商品配置中；免费基础人物也不能创建为商品。素材的文件格式、可用类型、免费属性和穿戴槽位由目录定义，管理页只能选择适用的素材。

素材以不可覆写的版本标识安装到独立持久目录。发布目录被替换后，历史订单仍可读取已安装素材；同一标识的新内容不能覆盖旧内容，新增内容应采用新标识。已购物品可以通过稳定物品身份获得新增的营地能力，成交事实保持原样。

2026-10-29 的人物与固定穿戴改造按新模型实施，明确不提供旧人物映射、旧订单权益转换或旧数据迁移。这是已确认的实施范围，不是待验证的兼容能力；素材持久化规则也不代表旧人物订单可以自动转换。数据库结构不兼容时的安装处置见 [运行手册](../ENGINEERING/OPERATIONS.md)。

## 验证边界

购买与装备检查应覆盖真实数据库中的双币扣款、库存竞争、重复请求、负余额、十饰品上限、单槽并发和商品删除后所有权。布局检查覆盖重放、目标卸下和草稿保留；人物检查覆盖免费选择、四槽隔离、默认衣物、动物切换以及画像与营地一致。

专题元数据列出相关测试入口，测试文件存在不代表本次执行通过。按改动选择验证，执行状态和设备限制见 [测试指南](../ENGINEERING/TESTING.md)。
