# 数据与一致性

## 数据归属与事实源

一个数据库服务唯一账户，账户身份固定为 `1`；它不提供租户隔离。扩展为多账户时必须重新设计归属、约束和授权，不能只开放注册。

表结构、索引和约束以编号 SQL 迁移为准，不在文档复制字段表。记录保存完成事实和奖励快照，订单保存成交事实与所有权，钱包提供当前余额，流水用于追溯和核对。配置变化不能改写已经发生的交易。

## 日期、数值与文本

业务日期使用 `YYYY-MM-DD`，按固定 `Asia/Taipei` 时区计算，周一为一周起点。设备时区不改变记录归属。创建和更新时间持久化为 UTC 毫秒，对外转为带时区的 RFC 3339；补录的所属日期与真实创建时间分开保存，不伪造历史完成时刻。

写操作取得事务后用一次服务端时间判断日期和权限，避免同一请求前后跨日。普通新增携带预期今天，日期变化时拒绝并要求刷新确认；已成功的同一幂等请求跨日仍恢复原结果。重试协议见 [HTTP API](HTTP_API.md)。

金币、钻石、次数、库存和价格采用整数。持久化前检查操作数及运算结果是否在 JavaScript 安全整数范围内；溢出必须使整个事务失败。余额允许负值，奖励与价格非负，空库存表示不限量。稳定 ID 与名称分离，改名不改变对象身份。

业务文本保存为纯文本并按 Unicode 码点检查长度；名称等字段按各自规则处理空白。配置拥有普通限值，公开接口拥有字段和值域，文档只说明其语义。

## 单连接和短事务

应用共用一个数据库连接池，最多一个打开连接和一个空闲连接。每个物理连接都启用外键、忙等待和完整同步；打开数据库时启用并核对 WAL。数据库及 WAL 文件必须放在本机文件系统，不能放到同步盘或共享网络盘。

写事务使用 `BEGIN IMMEDIATE`，在读取并判断可变业务状态前取得写权限。SQLite 仍可能遇到其他进程持有的锁；锁忙转换为可重试错误，不在服务中叠加无界重试。WAL 不会让单连接池自动拥有并行查询能力。

多条查询组成同一个汇总结果时，在短读取事务中取得一致快照。当前驱动在 `ReadOnly` 选项下使用普通读取事务；该选项是事务模式，不是禁止写入的权限机制，读取事务内部只执行查询。

所有事务内部查询和写入都使用传入的 `sql.Tx`，不能绕回 `sql.DB` 再申请唯一连接，也不能嵌套事务。读完并关闭 Rows 后再发起下一条查询。密码哈希、文件解码、上传和探测在事务外进行，进入事务后复核授权与必要状态。

事务失败整体回滚，只有 `Commit` 成功才能报告业务成功。客户端取消或超时不证明提交未发生，因此结果恢复仍遵守 [HTTP API](HTTP_API.md) 的原请求重试规则。

## 账务与快照

一次打卡发奖、删除回收或购买扣款，必须将业务记录、钱包余额、不可修改的流水及成功幂等收据放在同一事务提交。流水的引用与事件类型受数据库约束，唯一索引阻止同一记录重复发奖或回收、同一订单重复扣款。零奖励与免费购买也是合法经济事实。

钱包余额始终应等于对应币种流水变化量之和。系统没有手工改余额接口；发现差值时应调查交易与日志，不能静默改数掩盖问题。删除打卡按原奖励回收，即使余额因此为负，已购所有权也不会被撤销。业务条件见 [打卡](../FEATURES/CHECKIN.md) 和 [商店](../FEATURES/SHOP.md)。

记录保存名称、图标和奖励快照；订单保存类型、名称、素材与价格等成交快照。删除配置保留历史引用，普通查询过滤已经软删除的记录。记录删除后清空文字并解除媒体引用，保留最少的业务与回收依据。

媒体文件先完成内容校验和私有存储，再由业务事务关联；数据库与文件系统不共享原子事务。中断后的未关联文件由生命周期规则回收，详细状态和恢复见 [媒体](../FEATURES/MEDIA.md)。

历史图标与装扮素材使用不可覆写的版本标识，安装到持久目录，不能依赖旧发布目录。素材不进入普通媒体清理；商品删除或程序更新不应让已购素材消失。素材选择与所有权语义见 [商店](../FEATURES/SHOP.md)。

## 迁移与兼容

SQL 文件按连续编号加载，每个已应用版本保存文件名和内容校验值。`migrate` 先核对全部已应用历史，再将待应用 SQL 与对应版本记录一次提交；任何步骤失败都不记为成功。重复执行没有待应用版本时不重复建表。

服务启动只运行结构检查，要求历史与当前程序完全匹配。缺少新版本时提示显式迁移；文件名、校验值不匹配或数据库比程序更新时拒绝启动。禁止通过删除迁移记录绕过检查。

项目尚未上线，当前阶段不要求兼容旧数据库。破坏性结构更新可以调整现有建表脚本，更新后由开发者显式重置数据库，并按当前结构重新写入测试数据；不为旧数据增加转换逻辑。正常启动仍严格核对历史，不自动清空或修复。迁移器只对已应用文件完全相同的数据库执行追加迁移，不能据此承诺旧库可升级。

开发重置命令删除配置指定的数据库及其 WAL、SHM 文件，再复用当前建表和测试初始化流程。原有账户、业务记录和会话全部清空；媒体、素材及临时目录保留，旧媒体的数据库引用随重置丢失。执行前必须停止使用该数据库的服务；命令不做交互确认，只有建库和测试初始化都成功才报告完成。操作步骤见 [数据库迁移与不兼容处理](../ENGINEERING/OPERATIONS.md#数据库迁移与不兼容处理)。

回退程序前同样核对迁移兼容性，不能只换二进制掩盖数据库差异。只读结构状态检查不创建缺失数据库，也不证明业务数据正确。具体命令及发布处理见 [运行手册](../ENGINEERING/OPERATIONS.md)。

## 恢复与验证边界

受支持的恢复包括事务回滚、锁释放后的原请求重试、进程重启、上传中断与清理重试。这些能力不代表磁盘损坏或数据丢失后的恢复承诺；备份与备份恢复不在当前范围内。

锁竞争和快照应由真实文件数据库及独立连接证明；提交失败与磁盘满应在真实故障边界证明，不能以 Mock 代替。本专题列出的测试是查阅候选，不代表本次执行状态。按改动选择验证，见 [测试指南](../ENGINEERING/TESTING.md)。
